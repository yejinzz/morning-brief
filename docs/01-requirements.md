# 01 · 요구사항 정의 (Requirements)

> Morning Brief · 설계 문서 1/8 · 작성일 2026-11-10 · 상태: 초안(승인 대기)

본 문서는 `docs/morning-brief-design-plan.md`(설계 요청서)를 근거로 범위·사용자 시나리오·MVP/제외 범위·수용 기준을 확정한다. 기술 스택·무료 티어 검증은 `03-tech-stack.md`, `07-infrastructure.md`에서 다룬다.

## 1. 제품 개요

**Morning Brief**는 개인 1인(소유자)이 매일 출근 전 **5분 이내**에 국내외 시사·경제·AI·개발·테크 분야의 중요 뉴스를 파악하기 위한 **모바일 우선 PWA 뉴스 브리핑 서비스**다.

- 매일 **07:00 Asia/Seoul(목표)**에 클라우드 배치가 뉴스를 수집·분석·선정하여 그날의 브리핑을 생성한다.
- 생성이 **정상 완료된 후에만** Web Push 알림을 보낸다. 앱을 강제 실행하지 않는다.
- 사용자는 알림을 누르거나 홈 화면 PWA를 열어 그날(또는 지난) 브리핑을 읽는다.

### 1.1 최우선 제약 (비기능 요구사항 #0)

**월 운영비 0원.** 유료 플랜·유료 API·유료 체험 크레딧·결제 수단 등록 필수 서비스·한도 초과 시 자동 과금 구성은 사용하지 않는다. 무료 한도 소진 시 안전하게 **중단**하고 마지막 정상 브리핑을 유지한다. 무료 서비스의 정책 변경·스케줄 지연·일시 중지로 인해 **정확한 07:00 실행과 영구 무중단을 보장할 수 없음**을 명시적으로 수용한다.

## 2. 사용자 및 역할

| 역할 | 설명 | 권한 |
|---|---|---|
| **소유자(Owner)** | 유일한 인간 사용자. 서비스 소유자 본인. | 브리핑 조회, 설정 변경, 푸시 구독 |
| **배치 시스템(Pipeline)** | 서버 측 자동 실행 주체. 사람 아님. | 뉴스 수집·분석·선정·저장·푸시 발송 |

- 소유자 계정은 1개. 멀티 유저는 범위 외(스키마는 `user_id`로 확장 가능하게 두되 MVP는 단일 사용자).

## 4. 핵심 사용자 시나리오 (User Scenarios)

### US-1 · 아침 브리핑 확인 (해피 패스)
1. 07:00 전후 배치가 브리핑을 정상 생성한다.
2. 소유자 폰에 Web Push 도착: "오늘의 주요 뉴스 N건 · 카테고리별 HIGH 건수 · 예상 읽기 N분".
3. 알림을 누르면 PWA가 **해당 날짜 브리핑**으로 딥링크된다.
4. 상단에 날짜·생성 완료 시각·**오늘의 한 줄 브리핑**·수집 수/HIGH 수/예상 읽기 시간이 보인다.
5. 전체 탭에서 HIGH 기사 카드(최대 15건)를 5분 이내로 훑는다. 필요 시 카테고리 탭으로 좁힌다.
6. 관심 기사는 원문 링크로 이동, 읽은 기사는 읽음 처리된다.

### US-2 · 지난 브리핑 조회
- 소유자가 날짜를 선택해 과거 브리핑을 읽는다(보관 기간 내).

### US-3 · HIGH 0건인 날
- 중요 뉴스가 없으면 임의 승격 없이 "오늘은 HIGH로 분류된 뉴스가 없습니다" 상태를 보여준다.
- 해당 날 푸시 발송 여부는 **설계 결정 항목 D-1**(§9) 참조.

### US-4 · 생성 실패/부분 실패
- 배치가 실패하면 **성공 알림을 보내지 않고**, PWA는 마지막 정상 브리핑을 계속 보여준다.
- 부분 실패(일부 소스/일부 기사 분석 실패)는 완료 기준 충족 시 "일부 분석 미완료" 표시와 함께 브리핑을 낼 수 있다(완료 기준은 `04-news-pipeline.md`).

### US-5 · 푸시 구독/권한
- 소유자가 PWA에서 명시적으로 알림 권한에 동의하고 구독한다. 해지도 가능하다.
- iOS는 **홈 화면 설치 후에만** 푸시가 동작한다(제약은 `07-infrastructure.md`에서 검증).

### US-6 · 무료 한도 소진
- AI/DB/스케줄러 무료 한도 소진 시 자동 과금 없이 중단하고, 상태를 기록하며, 마지막 정상 브리핑을 유지한다.

### US-7 · 설정
- 소유자가 테마(라이트/다크), 관심 카테고리, 알림 on/off를 변경한다.

## 5. 기능 요구사항 (FR)

### 5.1 수집·선정·분석
- **FR-1** 매일 07:00 KST 목표로 클라우드에서 배치 실행(사용자 기기 전원과 무관).
- **FR-2** 최근 24시간 기사 우선 수집, 부족 시 최대 72시간까지 확대.
- **FR-3** 카테고리별 후보 10~20건 목표 수집(무료 소스·호출 제한에 맞춰 조정).
- **FR-4** URL 정규화, 제목 유사도·동일 사건 그룹화, 이전 브리핑과의 중복 검사.
- **FR-5** 파이프라인 순서 **고정**: 후보 수집 → 정규화·중복 제거 → 출처·관련성 필터 → AI 영향도 분석 → 카테고리별 최대 3건 선정 → HIGH만 표시. **최신 3건을 먼저 고정하고 분석을 생략하지 않는다.**
- **FR-6** AI는 `HIGH/MEDIUM/LOW` 분류 + 근거 + 3문장 이내 요약 + 개발자 관련성을 **구조화된 JSON**으로 반환.
- **FR-7** AI는 확인하지 못한 사실을 생성하지 않는다. 제목·설명만으로 분석했다면 근거 한계를 표시. 검증 불가·출처 충돌은 보류/별도 상태.
- **FR-8** 하루 최대 15건(카테고리별 최대 3건). 수량을 위해 부적절한 기사를 억지로 채우지 않는다.
- **FR-9** HIGH가 없으면 임의 승격하지 않는다. 비노출 분석 결과도 저장하되 기본 UI에는 HIGH만 노출.
- **FR-10** 당일 HIGH로 **오늘의 한 줄 브리핑(1~2문장)** 생성 + 예상 읽기 시간 표시. 전체 기본 브리핑 5분 이내 분량 목표.

### 5.2 PWA
- **FR-11** 모바일 우선 PWA. Android/iOS 홈 화면 설치, 데스크톱 브라우저 조회 지원.
- **FR-12** 기본 화면 요소: 날짜, 생성 완료 시각, 한 줄 브리핑, 수집 수·HIGH 수·예상 읽기 시간, 뉴스 목록.
- **FR-13** 탭 6종(전체 + 5개 카테고리).
- **FR-14** 카드 요소: 제목, 카테고리, 3문장 이내 요약, HIGH 판단 근거, 출처, 발행 시각, 원문 링크.
- **FR-15** 지난 날짜 브리핑, 읽음 상태, 관심 카테고리, 알림 설정, 라이트/다크 모드.
- **FR-16** 상태 UI 정의: 로딩, 생성 중, HIGH 0건, 카테고리 0건, 네트워크 오류, 마지막 정상 브리핑, 오프라인 캐시.

### 5.3 Web Push
- **FR-17** 07:00에 앱을 강제 실행하지 않는다. 브리핑 **정상 완료 후** 푸시 발송.
- **FR-18** 알림 내용: 오늘의 주요 뉴스 N건, 카테고리별 HIGH 건수, 예상 읽기 시간. 누르면 해당 날짜 브리핑 딥링크.
- **FR-19** 명시적 권한 동의, 구독·해지, VAPID 키 관리, 만료 구독 제거, 실패 재시도, 날짜·사용자별 중복 발송 방지.
- **FR-20** 브리핑 생성 실패 시 성공 알림 금지.

### 5.4 보안·인증
- **FR-21** 개인 계정 1개, 공개 회원가입 비활성화, 최소 인증, 인증된 사용자만 조회, RLS.
- **FR-22** 서버 전용 비밀키(AI 키·서비스 권한 키)는 브라우저에 전달하지 않는다.

## 7. MVP 범위 / 제외 범위

### 7.1 MVP (포함)
- 5개 카테고리 뉴스 수집(검증된 무료 소스), 정규화·중복 제거.
- 단일 무료 AI 모델로 영향도 분석(JSON), 카테고리별 최대 3건·전체 최대 15건 선정, HIGH만 노출.
- 한 줄 브리핑 + 예상 읽기 시간.
- PWA: 전체+5개 탭, 카드, 날짜별 조회, 읽음 상태, 테마·알림 설정, 상태 UI.
- 단일 사용자 인증(최소), RLS.
- 클라우드 스케줄 배치(07:00 KST 목표) + 수동 재실행.
- 브리핑 성공 후 Web Push.

### 7.2 제외 (Out of Scope, MVP)
- 멀티 유저·공개 회원가입·소셜 로그인.
- 기사 원문 전문 저장·재배포, 뉴스 전문 검색 엔진.
- 유료 뉴스 API·유료 AI 모델·유료 호스팅.
- 댓글·공유·소셜 기능, 북마크 폴더, 추천 알고리즘 고도화.
- 다국어 UI(한국어 우선), 이메일/카카오 등 추가 알림 채널(Web Push만).
- 실시간 업데이트(하루 1회 배치 기준).
- 네이티브 앱(스토어 배포).

## 8. 수용 기준 (Acceptance Criteria)

- **AC-1** 사용자 기기가 꺼져 있어도 클라우드 배치가 실행되어 브리핑이 생성된다(스케줄러 지연은 허용, 실행 자체는 기기 독립).
- **AC-2** 파이프라인은 "분석 후 선정" 순서를 지킨다. 최신순 상위 N건을 분석 없이 고정하지 않는다.
- **AC-3** 하루 선정은 카테고리별 ≤3건, 전체 ≤15건이며, 기본 UI에는 HIGH만 노출된다.
- **AC-4** HIGH 0건인 날 임의 승격이 없고 전용 상태가 표시된다.
- **AC-5** 브리핑 생성 실패 시 성공 푸시가 발송되지 않고, PWA는 마지막 정상 브리핑을 보여준다.
- **AC-6** 동일 날짜 재실행 시 중복 브리핑/중복 푸시가 생기지 않는다(멱등).
- **AC-7** 어떤 경로에서도 유료 서비스 호출·자동 과금이 발생하지 않는다. 무료 한도 소진 시 안전 중단된다.
- **AC-8** AI 키·서비스 권한 키가 브라우저 번들·네트워크 응답에 노출되지 않는다.
- **AC-9** 모바일에서 전체 브리핑을 5분 이내 분량으로 읽을 수 있다.
- **AC-10** iOS 홈 화면 설치 PWA에서 푸시 수신이 동작한다(브라우저/OS 제약은 문서화).
