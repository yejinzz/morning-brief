# Morning Brief — 구현 플랜 요청서

> Claude Code 전달용 · **설계 승인 후 사용** · 프로젝트 `morning-brief`

## 1. 전제 조건

`docs/01-requirements.md`부터 `docs/08-risks.md`까지 **승인된 설계 문서**를 읽고 실제 개발을 위한 구현 플랜을 수립한다. 설계가 아직 작성되지 않았거나 승인되지 않았다면 작업을 중단하고 사용자에게 확인을 요청한다.

**이번 요청은 구현 플랜 문서 작성만 수행한다.** 애플리케이션 코드 작성, 패키지 설치, DB·클라우드 리소스 생성, 배포를 하지 않는다. 사용자가 구현 플랜을 승인한 후에만 M0부터 개발한다.

## 2. 절대 제약 — 월 운영비 0원

- 유료 플랜·유료 API·유료 체험 크레딧·결제 수단 등록 필수 서비스 금지.
- 무료 한도 초과 시 자동 과금이 발생하지 않아야 한다.
- 모든 마일스톤에서 **무료 사용량·예상 사용량·한도 초과 시 중단 정책**을 확인한다.
- 무료 AI 한도 소진 시 유료 모델로 전환하지 않고 분석을 중단한다.
- 무료 서비스의 정책 변경·스케줄 지연·일시 중지 위험은 테스트·운영 계획에 반영한다.
- 무료 조건을 검증할 수 없거나 승인된 설계와 충돌하면 임의 구현하지 않고 사용자에게 보고한다.

## 3. 기능 범위 및 핵심 계약

### 3.1 뉴스 파이프라인

매일 **07:00 Asia/Seoul** 목표로 클라우드 실행. 최근 24시간 우선·최대 72시간, 5개 카테고리(국내 시사 / 경제·국제 / AI·LLM / 개발·인프라 / 기타 테크), 후보 카테고리별 10~20건 목표, 정규화·중복 제거, AI 영향도 분석 후 카테고리별 최대 3건 선정, HIGH만 기본 브리핑 표시. 하루 최대 15건, 5분 이내 읽기. 출처·발행 시각·원문 링크·요약·판단 근거 보존. 부적절한 기사를 수량 때문에 채우지 않는다.

### 3.2 모바일 PWA

React + Vite + TypeScript 기반 후보(최종 스택은 승인 설계 준수). 전체 기본 탭과 5개 카테고리 탭, 오늘의 한 줄 브리핑, 기사 카드, 지난 날짜 조회, 읽음 상태, 알림·테마 설정, 로딩·빈 상태·오류·오프라인 대응. 모바일 우선, Android/iOS 설치 조건 검증.

### 3.3 푸시 알림

브리핑 **정상 완료 후** Web Push 발송. 날짜별 중복 방지, 권한 동의·구독·해지, 만료 구독 정리, 발송 실패 재시도, 해당 날짜 딥링크. 브리핑 실패 시 성공 알림 금지. HIGH 0건 정책은 승인된 설계 기준으로 처리.

### 3.4 보안

개인 계정 1개 중심, 공개 회원가입 차단, 인증·RLS·최소 권한, 브라우저에 AI/API 서비스 키 미노출. 서버 비밀키는 승인된 무료 운영 환경의 Secret 기능에만 저장.

## 4. 마일스톤 계획

아래 마일스톤은 **초안**이다. 승인 설계의 실제 기술·배포 구조에 맞춰 작업 순서와 파일 경로를 조정하되 변경 이유를 기록한다.

### M0 — 프로젝트 기반 및 계약 확정

- 확정된 저장소 구조(`apps/web`, `services/news-pipeline` 등)를 설계에 맞춰 정의.
- 코드 품질 도구, 환경 변수 정책, `.env.example`, 비밀키 노출 방지 규칙.
- DB 스키마·RLS·마이그레이션·API 응답 계약·AI JSON Schema의 구현 순서.
- 로컬 개발과 Mock 데이터 실행 방식, 무료 서비스 계정 준비 체크리스트.
- **완료 기준:** 신규 개발자가 무료 환경에서 로컬 실행 절차를 재현할 수 있고, API/DB 계약 및 비밀키 관리 정책이 문서화되어 있음.

### M1 — 뉴스 수집 엔진

- 카테고리별 검증된 무료 RSS/API 어댑터 구현 계획.
- 발행 시각·URL·출처 정규화, 24→72시간 확장, 동일 기사·동일 사건 중복 제거.
- 후보 수집량 조절, 무료 호출량 상한, 소스별 타임아웃·재시도·부분 실패 처리.
- 수집 결과 DB 저장 및 수집 실행 로그.
- **완료 기준:** 테스트 픽스처로 중복 제거·발행 시각 필터·카테고리 분류·소스 장애 격리를 재현하고, 무료 호출 상한을 넘지 않음.

### M2 — AI 분석 및 브리핑 생성

- 승인된 무료 AI 모델 하나 연동, 교체 가능한 최소 인터페이스.
- HIGH/MEDIUM/LOW 기준, 요약·판단 근거·개발자 관련성 JSON Schema 검증.
- 사전 필터링, 분석 배치·캐시, 일일 요청·토큰 상한, 실패 재시도 제한.
- **분석 후** 카테고리별 최대 3건 선정, HIGH만 노출용 브리핑 생성.
- 한 줄 브리핑, 예상 읽기 시간, HIGH 0건 처리, 동일 날짜 멱등성.
- **완료 기준:** AI 응답 오류·한도 소진·후보 부족·HIGH 0건·동일 날짜 재실행을 테스트하고, 유료 API 호출 없이 브리핑 데이터가 생성됨.

### M3 — 모바일 PWA

- 인증된 브리핑 조회, 날짜별 조회, 전체 및 5개 카테고리 탭.
- 요약·출처·시각·판단 근거·원문 링크를 갖춘 뉴스 카드.
- 읽음 상태, 테마·알림 설정, 접근성·반응형, 빈 상태·오류·이전 브리핑.
- PWA 매니페스트, 서비스 워커, HTTPS·캐시 정책, 설치 UX.
- **완료 기준:** Android/iOS 브라우저 및 홈 화면 설치 시나리오를 검증하고, 모바일에서 핵심 뉴스를 5분 이내 읽을 수 있도록 표시함.

### M4 — 예약 실행 및 Web Push

- 승인된 무료 스케줄러에서 KST 07:00 목표 실행, 시간대 변환, 수동 재실행.
- 실행 중복 방지, 실패 상태 기록, 단계별 재시도, 완료 상태 정의.
- VAPID·구독 관리·구독 만료 처리·발송 이력·날짜별 중복 방지.
- 브리핑 성공 후에만 알림 발송, 딥링크, iOS 홈 화면 설치 조건 안내.
- 무료 스케줄러 지연·누락·DB 일시 중지 시 대처 방법.
- **완료 기준:** 예약 실행 및 수동 재실행, 성공·실패 알림 분기, 중복 푸시 방지, 구독·해지를 재현하고 별도 과금이 없음.

### M5 — 배포·통합 검증·운영 안정화

- 무료 정적 호스팅·DB·스케줄러 설정 및 Secret 점검.
- 통합/E2E 테스트, 모바일 성능·접근성·오프라인·알림 테스트.
- 운영 로그, 장애 확인, 재실행, 데이터 보관·정리, 무료 한도 모니터링.
- README·배포 가이드·운영 매뉴얼·무료 정책 변경 시 대응 문서.
- **완료 기준:** 사용자 기기가 꺼져 있어도 클라우드 배치가 실행되며, 브리핑 조회·푸시·장애 복구가 확인되고 유료 서비스·자동 과금 경로가 없음. 정확한 07:00 실행 보장은 무료 플랫폼 제약을 명시함.

## 5. 마일스톤별 필수 작업 명세 형식

각 M0~M5에 대해 다음을 빠짐없이 작성한다.

1. 목표·사용자 가치
2. 선행 조건·의존성
3. 세부 작업 체크리스트(Claude Code가 한 번에 구현·테스트할 수 있는 크기)
4. 생성·수정할 예상 디렉터리 및 파일
5. DB·API·데이터 계약 및 예외 처리
6. 단위·통합·E2E 테스트 시나리오
7. 무료 서비스 사용량·비밀키·과금 위험 점검
8. Definition of Done(완료 조건)
9. 예상 위험·대응 및 사용자 확인 필요 사항
10. 완료 보고 형식 및 다음 단계 진입 조건

설계가 확정하지 않은 경로·테이블·기술을 임의로 사실처럼 정하지 않는다. 필요한 결정은 명시적으로 제안한다.

## 6. 필수 테스트 매트릭스

- **수집:** 24/72시간 경계, 기사 부족, 소스 장애, 타임아웃, URL·사건 중복.
- **AI:** 정상 JSON, 잘못된 JSON, 환각 방지, HIGH/MEDIUM/LOW 경계, 무료 한도 소진, 요청·토큰 상한.
- **선정:** 카테고리별 최대 3건, 전체 최대 15건, 분석 후 선정, HIGH만 노출, HIGH 0건, 읽기 시간.
- **DB:** 날짜별 중복 실행, 제약조건, RLS, 권한 없는 조회, 데이터 보관.
- **PWA:** 탭·날짜·원문 링크, 읽음 상태, 모바일 화면, 설치, 오프라인·오류·캐시.
- **푸시:** 권한 거부, 구독·해지, 성공·실패, 딥링크, 만료 구독, 중복 전송, iOS 제약.
- **운영:** KST 시간대, 예약 실행 지연, 수동 재실행, 비밀키 노출 검사, 무료 한도 초과 시 중단, 서비스 일시 중지.

각 테스트에 자동화 가능 여부, Mock/실서비스 구분, 통과 기준, 수행 마일스톤을 기재한다.

## 7. 구현 작업 진행 원칙

- 설계 문서와 충돌하면 **구현을 멈추고 변경 승인을 요청**한다.
- M0부터 순차적으로 진행하되 각 마일스톤은 완료 보고 및 승인 후 다음 단계로 이동한다.
- 외부 계정 생성, 인증키 입력, 서비스 활성화가 필요한 단계는 사용자 작업을 구분한다.
- 과도한 추상화, 마이크로서비스, 불필요한 상태관리 라이브러리를 도입하지 않는다.
- API/DB 계약을 먼저 확정하고 Mock 테스트를 우선한다.
- 무료 한도·유료 전환 위험을 매 단계 확인한다.
- 실패 시 이전 정상 브리핑을 유지하고, 성공을 가장한 알림을 보내지 않는다.
- 프로젝트 Git 커밋 메시지는 사용자가 별도로 지정한 규칙이 있으면 그 규칙을 따른다.
