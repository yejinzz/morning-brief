# 09 · 구현 플랜 — 전체 로드맵 (Implementation Plan)

> Morning Brief · 구현계획 1/4 · 작성일 2026-11-10 · 상태: 초안(승인 대기)
> 승인된 설계(01~08) 및 결정 항목 D-1~D-5 기준. **M0 코드는 본 구현계획(09~12) 승인 후 시작.**

---

## 1. 승인된 전제 (Baseline)

- **스택(D-5)**: React+Vite+TS+Tailwind+PWA / Cloudflare Pages / Python 파이프라인 / Gemini Flash-Lite 무료 / Supabase Free / GitHub Actions(Public) / Web Push+VAPID.
- **결정**: D-1 HIGH 0건 **푸시 미발송** · D-2 읽음상태 **로컬** · D-3 **Supabase Auth 최소(단일 계정)** · D-4 **카테고리 묶음 AI 분석** · D-5 스택 확정.
- **절대 제약**: 월 0원. 유료 폴백·결제 등록 금지. 한도 초과 시 중단.

---

## 2. 전체 로드맵 (M0 → M5)

| MS | 이름 | 목표 | 핵심 산출 | 외부 계정 필요 |
|---|---|---|---|---|
| **M0** | 기반·계약 확정 | 저장소 구조, 계약(DB/API/AI Schema), 로컬·Mock 실행 | 스켈레톤, 마이그레이션, `.env.example`, Mock | (준비 체크리스트) |
| **M1** | 수집 엔진 | 무료 RSS/API 수집·정규화·중복제거 | `news-pipeline` 수집부 + 테스트 | - |
| **M2** | AI 분석·브리핑 | Gemini 분석(JSON), 선정, 브리핑 생성 | 분석·선정·브리핑 + 테스트 | Gemini 키(사용자) |
| **M3** | 모바일 PWA | 조회 UI, 탭/카드, 상태 UI, PWA | `apps/web` + 테스트 | Supabase(사용자) |
| **M4** | 스케줄·푸시 | cron 실행, Web Push 발송 | Actions 워크플로 + 푸시 + 테스트 | VAPID, Supabase |
| **M5** | 배포·검증·안정화 | 무료 배포, E2E, 운영·복구 | 배포, 통합테스트, README | Cloudflare(사용자) |

## 3. 의존성 그래프

```
M0 (기반·계약)
 ├──▶ M1 (수집) ──▶ M2 (AI·브리핑) ──┐
 │                                    ├──▶ M4 (스케줄·푸시) ──▶ M5 (배포·안정화)
 └──▶ M3 (PWA) ───────────────────────┘
```
- M1·M3는 M0 이후 병렬 가능(계약 확정 시). 단 사용자 승인은 순차.
- M4는 M2(브리핑 생성)+M3(딥링크 대상)+푸시 구독 UI 전제.
- M2/M3는 **Mock 데이터**로 먼저 구현·테스트(실계정 최소화).

---

## 4. 무료 운영 게이트 (매 마일스톤 통과 조건)

각 마일스톤 완료 전 반드시 확인:
1. 유료 API/서비스 호출 경로 없음.
2. 결제 수단 등록 불필요 유지.
3. 한도 초과 시 **중단**(자동 과금·유료 폴백 없음) 동작 확인.
4. 비밀키가 클라이언트 번들/로그에 노출되지 않음.
5. 무료 한도 대비 예상 사용량 재확인(변동 시 보고).

---

## 5. 작업 진행 원칙 (impl-plan §7 반영)

- 설계 충돌 시 **구현 중단 → 변경 승인 요청**.
- M0부터 순차. **각 마일스톤 완료 보고 + 사용자 승인 후** 다음 진입.
- 외부 계정 생성·키 입력·서비스 활성화는 **사용자 작업**으로 명확히 구분.
- API/DB 계약 먼저 확정 → Mock 테스트 우선 → 실서비스 연동.
- 과도한 추상화·마이크로서비스·불필요 상태관리 금지.
- 실패 시 이전 정상 브리핑 유지, 성공 가장 알림 금지.
- 커밋: gitmoji 컨벤션(회사 규칙) 사용.

## 6. 사용자 준비 체크리스트 (마일스톤별)

| 시점 | 사용자 작업 | 비고 |
|---|---|---|
| M0~M2 전 | (선택) Gemini 무료 키 발급 | M2 실연동 시 필요, 그전엔 Mock |
| M3 전 | Supabase 무료 프로젝트 생성, 키 확보 | 결제 비활성 |
| M4 전 | VAPID 키쌍 생성 | `web-push generate-vapid-keys` |
| M5 전 | Cloudflare Pages 프로젝트(GitHub 연동) | 결제 비활성 |
| 전 구간 | GitHub Actions Secret 등록 | 이미 public repo 존재 |

→ 모든 계정은 **결제 수단 등록 없이** 생성.

## 7. 완료 보고 형식 (공통)

각 마일스톤 종료 시:
1. 구현 범위·산출 파일
2. 테스트 결과(통과/실패 수, 커버 시나리오)
3. 무료 운영 게이트 체크 결과
4. 예상 사용량·과금 위험 재확인
5. 미해결·결정 필요 항목
6. 다음 마일스톤 진입 조건

→ 보고 후 **사용자 승인 대기**. 승인 전 다음 마일스톤 미착수.
